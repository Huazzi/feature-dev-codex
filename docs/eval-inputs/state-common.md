# 状态选型评估输入

这是隔离的合成项目资料，只评估方案判断，不代表真实服务或运行验证。无需编写代码、连接数据库或发送短信。

## 需求

- 用户向自己的手机号请求验证码，验证码五分钟后失效；错误次数受限，同一验证码只能成功使用一次。
- 验证成功后建立二十分钟的独立临时会话；会话到期或退出后不能继续访问。
- 验证码或临时会话状态丢失时，允许拒绝当前请求，用户重新验证。结果未知时不能直接放行。
- 成功使用验证码后建会话失败，允许本次操作失败并重新获取验证码；不要求恢复原验证码。
- 记录开始、结束及业务操作的脱敏审计事件，现有审计服务持久保存九十天；审计内容不包含验证码或完整会话凭据。
- 在基础场景中，产品没有要求验证码状态、临时会话与审计事件处于同一个提交事务。若具体失败行为影响这些要求，请在方案中指出。

## 合成仓库的已核实事实

- 已有共享 Redis 客户端、TTL 缓存及脚本执行入口；导入任务使用带 TTL 的原子占位，限流服务使用计数器。部署故障下的恢复行为仍需验证。
- `CacheStore.put(key, value, ttl)` 的失败日志会输出 value；允许修改这一封装的日志，或使用相同客户端建立不输出敏感值的小适配器。
- 已有 MySQL 事务边界、条件更新调用和审计服务 `AuditService.append(event)`。审计服务可在本地事务中写入，但默认接口不将 Redis 操作纳入 SQL 提交。
- 当前没有验证码挑战表，也没有临时会话表；没有已确定的两者存储方案。
- 这些事实是本评估的输入，不能声称已在真实项目中检查这些类或运行测试。
